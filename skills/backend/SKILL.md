# 后端

## 动手前
1. `stack_probe` 确认语言与框架（Express/Fastify/NestJS/Hono/Django/FastAPI/Spring/Gin）。
2. 找到既有的路由注册方式、请求校验方式、错误类型、日志封装、鉴权中间件，按同构写法实现。
3. 找到既有的集成/契约测试，确认测试如何启动依赖（内存库、容器、fixture）。

## 实现准则
- **契约先写**：request/response 的类型或 schema 先定，再写实现；错误码与错误体沿用既有格式。
- **分层不越界**：handler 只做校验与编排，业务逻辑进 service，IO 进 repository；不在 handler 里写 SQL。
- **事务边界明确**：多写操作要么同一事务，要么显式补偿；不依赖调用方顺序正确。
- **幂等与重试**：写接口与后台任务要说明幂等键或去重策略。
- **可观测**：关键路径复用既有 logger，字段名与既有日志一致；新增指标需说明用途。
- **鉴权默认拒绝**：新接口默认需要鉴权，公开接口必须显式标注理由。

## 完成前必查
- [ ] lint / typecheck 通过
- [ ] 单测覆盖新增分支；接口改动跑契约/集成测试
- [ ] 错误路径有测试（参数非法、未授权、依赖失败）
- [ ] 未修改无关接口的对外行为
- [ ] 若改了 schema 或错误格式，列出受影响的调用方

## 反模式
- 绕开既有 DI / logger / 错误基类另起一套
- 在循环里逐条查库
- 捕获异常后静默返回 200

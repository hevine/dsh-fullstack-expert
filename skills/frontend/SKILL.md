# 前端

## 动手前
1. 用 `stack_probe` 确认框架（Next/React/Vue/Svelte/Angular）、构建工具与现有命令。
2. 读取相邻 2-3 个同类组件，提取既有模式：目录命名、props 风格、样式方案（CSS Modules / Tailwind / styled）、i18n 与图标用法。
3. 确认状态管理的既有约定（Context、store、server state 库），不要为单个页面引入新模式。

## 实现准则
- **改动面最小**：优先改现有组件，新增文件只在确实需要新边界时创建。
- **契约先行**：跨组件/跨层数据用类型或 schema 定义，禁止 `any` 兜底。
- **样式跟随体系**：沿用设计 token 与间距刻度，不写魔法数字；响应式断点与既有断点一致。
- **可访问性**：语义标签、`label` 关联、键盘可达、对比度不低于既有基准。
- **性能**：不在渲染路径做同步重计算；大列表沿用既有虚拟化/分页方案。

## 完成前必查
- [ ] lint 通过（命令取自探测结果）
- [ ] typecheck 通过（若项目有）
- [ ] 相关单测/组件测试通过；无测试则说明覆盖缺口
- [ ] build 通过（改动涉及构建配置时必做）
- [ ] 未引入未经请求的新依赖

## 反模式
- 顺手升级框架大版本、顺手替换样式方案
- 用一个全局状态解决局部问题
- 仅为让测试变绿而放宽断言
